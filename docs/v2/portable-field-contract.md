# Grant Assistant v2 — portable field contract
Status: proposed v0.1 contract for review (2026-11-02). Logical collections do not imply one physical table each. No production migration authorized.

## Global rules
- Store durable logical IDs as text (UUID generated by installer for local entities); never use Airtable record ID or Sheets row index as cross-platform identity.
- Dates use ISO 8601 YYYY-MM-DD; timestamps UTC RFC 3339; monetary values numeric with currency code (default USD only when confirmed); booleans true/false/blank unknown.
- Empty is unknown, not false, ineligible, or zero. Lists use JSON arrays in Sheets and native multi-select/link fields in Airtable only where lossless.
- Provenance and last-verified timestamps remain distinct from discovery and update timestamps. Retain canonical source URLs. Do not put private applicant information into shared Grant Intelligence.
- Human-owned stage fields cannot be changed by automated scan writes.

## Collection: organization_grant_roles (optional physical table, required logical ability)
role_id, organization_id, grant_id, role (funder, lead_applicant, co_applicant, subrecipient, partner, contractor, vendor, other), evidence_url, valid_from, valid_until, verification_status. A role belongs to an organization in a specific grant context.

## Collection: funder_restrictions (optional physical table)
restriction_id, organization_id, profile_id, reason, effective_from, expires_on, evidence_url, status. Restrictions must remain visible and never silently suppress grants.

## Collection: search_profiles (optional physical table)
search_profile_id, profile_id, name, search_terms, geography_override, beneficiary_override, program_id, active, updated_at. Program-specific profiles may narrow only explicitly requested scans; general scans remain broad.

## Adapter contract
- list/get/upsert by logical ID; search candidate duplicates by source_system + source_record_id, otherwise normalized canonical URL + cycle, then manual resolution if ambiguous.
- Writes are idempotent and preserve human-owned fields; no last-writer-wins overwrites of operator edits.
- Airtable: map logical IDs to Airtable record IDs internally, validate schema before writes.
- Sheets: one named tab per logical collection used; stable headers, JSON serialization for arrays, UUID lookups (never row-number joins), read-before-write and collision detection.
- Maintain per-install field mapping and migration version. No destructive schema changes without operator approval.

## Open for product and technical review
